# C++17：从语言机制到 ROS 2 工程

> 本文使用 **C++17** 作为学习基线。C++ 不只是给 C 添加类，重点在于**类型系统、对象生命周期、资源管理、泛型和标准库**。原笔记中的这些主题按“对象如何创建与销毁”的主线重新排列。

## 1. 编译与基本程序

```cpp
#include <iostream>
#include <string>

int main() {
    const std::string project = "ROS2";
    std::cout << "Hello " << project << '\n';
    return 0;
}
```

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -g main.cpp -o app
./app
```

C++ 程序通常经过预处理、编译/汇编与链接；头文件提供声明，源文件提供定义；符号重定义、漏链接等错误通常属于不同阶段。

## 2. 类型、const、auto 与引用

```cpp
int count = 3;
const int limit = 10;
double distance_m = 2.5;
auto ratio = distance_m / count;  // double

int value = 42;
int& ref = value;       // ref 是 value 的别名
const int& readonly = value;
```

- `auto` 是编译期类型推导，不等于动态类型。
- 引用通常必须初始化，并绑定到有效对象；`const T&` 常用于避免大对象拷贝且不允许修改参数。
- `T*` 可以表示可空指针，接口需要区分可选对象和必须存在的对象。

## 3. 函数、重载、默认参数与作用域

```cpp
#include <algorithm>

double clamp_speed(double speed, double low = 0.0, double high = 1.0) {
    return std::clamp(speed, low, high);
}
```

函数重载可按参数类型选择不同实现；默认参数解决常见调用形式，模板解决类型泛化。变量生命周期由**存储期**和作用域共同影响，不能简单等同于“写在函数内部就是栈，写在外部就是堆”。

## 4. std::string、vector 与容器

| 类型 | 用途 | 关键注意 |
| --- | --- | --- |
| `std::array<T,N>` | 固定大小数组 | 编译期长度 |
| `std::vector<T>` | 动态连续数组 | 扩容可能使指针/迭代器失效 |
| `std::string` | 可管理的字符串 | 与 C 字符串有不同的生命周期 |
| `std::map` | 有序键值容器 | 典型操作 $O(\log n)$ |
| `std::unordered_map` | 哈希键值容器 | 平均 $O(1)$，最坏可能退化 |

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

int main() {
    std::vector<int> nums{4, 1, 3, 2};
    std::sort(nums.begin(), nums.end());
    for (const int x : nums) std::cout << x << ' ';
}
```

不要把 `std::vector` 的迭代器在发生可能导致重分配的 `push_back` 之后继续当成有效迭代器使用。

## 5. 类、构造、封装与析构

```cpp
#include <string>
#include <utility>

class Device {
public:
    explicit Device(std::string name) : name_(std::move(name)) {}
    const std::string& name() const noexcept { return name_; }
private:
    std::string name_;
};
```

- `public` 是对外接口，`private` 表示实现细节。
- 构造函数建立对象不变量；析构函数在生命周期结束时清理资源。
- `explicit` 防止不希望的单参数隐式转换；`const` 成员函数承诺不通过普通路径修改成员。

## 6. RAII：用对象生命周期管理资源

RAII（Resource Acquisition Is Initialization）是现代 C++ 资源安全的核心：构造时获得资源，析构时释放。资源可以是堆内存、文件、锁、网络连接等。

```mermaid
flowchart LR
    A[对象构造] --> B[获取资源]
    B --> C[在作用域内使用]
    C --> D[作用域退出]
    D --> E[析构自动释放资源]
```

```cpp
#include <fstream>
#include <stdexcept>

void save_log() {
    std::ofstream out("log.txt");
    if (!out) throw std::runtime_error("cannot open log file");
    out << "robot online\n";
} // 自动关闭文件
```

## 7. 智能指针与所有权

| 工具 | 所有权语义 | 典型用途 |
| --- | --- | --- |
| `std::unique_ptr<T>` | 独占所有权，可移动不可复制 | 单一管理者 |
| `std::shared_ptr<T>` | 引用计数共享所有权 | 多方共享生命周期 |
| `std::weak_ptr<T>` | 不增加共享所有权 | 打破 shared_ptr 循环引用 |
| 原始指针 `T*` | 通常不表达所有权 | 可空观察、数组访问等 |

```cpp
#include <memory>
#include <iostream>

struct Sensor {
    void read() const { std::cout << "reading\n"; }
};

int main() {
    auto sensor = std::make_unique<Sensor>();
    sensor->read();
}
```

`std::shared_ptr` 不是“总是更安全”：不必要的共享会增加复杂度，循环引用还可能导致内存无法释放。

## 8. 拷贝、移动与右值引用

```cpp
#include <vector>
#include <utility>

std::vector<int> make_data() {
    return {1, 2, 3};
}

int main() {
    auto a = make_data();
    auto b = a;             // 复制数据
    auto c = std::move(a);  // 允许移动；a 仍是有效对象但状态不应假定
}
```

`std::move` 本身不搬运内存，它将表达式转换为允许移动的类别；是否实际移动由目标类型的构造/赋值操作决定。优先遵循零法则（Rule of Zero），让标准容器管理资源。

## 9. 继承、多态与 override

```cpp
#include <memory>

class Planner {
public:
    virtual ~Planner() = default;
    virtual bool plan() = 0;
};

class GridPlanner final : public Planner {
public:
    bool plan() override { return true; }
};

int main() {
    std::unique_ptr<Planner> planner = std::make_unique<GridPlanner>();
    return planner->plan() ? 0 : 1;
}
```

基类有虚函数且可能通过基类指针删除派生类对象时，需要合适的虚析构函数。接口继承表示行为契约；代码复用未必需要继承，组合常更灵活。

## 10. 模板、lambda 与 STL 算法

```cpp
#include <algorithm>
#include <vector>

template<class T>
T square(T x) { return x * x; }

int main() {
    std::vector<int> nums{1, 4, 2, 3};
    std::sort(nums.begin(), nums.end(),
        [](int a, int b) { return a > b; });
    return square(2) == 4 ? 0 : 1;
}
```

模板在编译期实例化泛型代码；lambda 是可调用对象表达式。lambda 捕获引用时必须保证所引用对象在调用期间仍然存活。

## 11. 异常、错误码与断言

- `throw` 用于报告异常情况，`catch` 在合适边界处理；异常传播中局部对象析构仍会执行。
- 错误码适用于 ABI 边界、嵌入式或禁止异常的项目，但调用者必须检查返回值。
- `assert` 用于开发期不变量，不应用来验证不可信外部输入；`NDEBUG` 可能移除断言。

## 12. 线程、互斥与竞态

```cpp
#include <iostream>
#include <mutex>
#include <thread>

std::mutex mu;
int counter = 0;

void run() {
    for (int i = 0; i < 1000; ++i) {
        std::lock_guard<std::mutex> lock(mu);
        ++counter;
    }
}

int main() {
    std::thread a(run), b(run);
    a.join(); b.join();
    std::cout << counter << '\n';
}
```

线程共享内存引入竞争条件。锁需要明确临界区与锁顺序；不应在持锁情况下执行耗时的未知回调。C++ 标准库线程与 ROS 2 executor 的回调调度不是同一层概念。

## 13. CMake 与项目组织

```text
my_project/
├── CMakeLists.txt
├── include/my_project/calculator.hpp
├── src/calculator.cpp
└── src/main.cpp
```

```cmake
cmake_minimum_required(VERSION 3.16)
project(my_project LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_executable(my_app src/main.cpp)
```

工程增长后再把共享代码整理为 `add_library`，明确公共头文件目录和目标级依赖，避免把所有编译参数写成全局设置。

## 14. C++ 如何落到 ROS 2 和 Nav2？

### 14.1 rclcpp 节点的生命周期

```mermaid
flowchart LR
    A[rclcpp::init] --> B[创建 Node]
    B --> C[设置订阅/发布/定时器]
    C --> D[rclcpp::spin / Executor]
    D --> E[rclcpp::shutdown]
```

```cpp
#include <memory>
#include <chrono>
#include "rclcpp/rclcpp.hpp"

class StatusNode : public rclcpp::Node {
public:
    StatusNode() : Node("status_node") {
        timer_ = create_wall_timer(
            std::chrono::seconds(1),
            [this]() { RCLCPP_INFO(get_logger(), "alive"); });
    }
private:
    rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char** argv) {
    rclcpp::init(argc, argv);
    rclcpp::spin(std::make_shared<StatusNode>());
    rclcpp::shutdown();
}
```

此例需要 ROS 2 Humble 的 C++ 包、`rclcpp` 依赖和相应 CMake/package.xml 配置。Nav2 插件通过继承相关接口定义规划器或控制器，源码学习要重点理解虚函数、生命周期、智能指针、坐标变换和异常处理。
